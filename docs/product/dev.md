# Bloomlog Development Notes

このファイルは、現在の開発方針と注意点を短くまとめる補助資料である。
プロダクト仕様の正本は `docs/product/overview.md` とする。

---

## 現在の開発フェーズ

- 記録アプリとしての基本機能は成立している。
- 現在の主な課題は、記録された情報を「その日の体験」として一瞬で思い出せる形にすること。
- 開発の中心は、思い出の意味付け、思い出アルバムの見せ方、視認性の改善である。

---

## 優先テーマ

1. 思い出の意味付け
   - 来場日ごとの印象を短く振り返れる状態にする。
   - 件数だけではなく、その日らしさが伝わる UI を優先する。

2. 思い出アルバムの改善
   - 種類別の記録を横断して見られる状態を維持する。
   - パビリオン画像や訪問回数など、視覚的に理解しやすい要素を活用する。

3. 可視化の改善
   - Area と Pavilion の関係を使い、訪問傾向が分かる表現を検討する。
   - UI 要件だけでデータ構造を歪めない。

---

## コレクション画面の扱い

### `/collection`

- 現行の思い出アルバム画面。
- 通常の改善対象はまずこの画面を基準に考える。

### `/collection-next`

- 思い出アルバム表現の検証ページ。
- 本採用が決まるまでは、既存 `/collection` への影響と分けて扱う。
- ユーザーに見える文言では、route path や内部値をそのまま出さない。

---

## データ構造の注意

### Pavilion

- ユーザーが訪問し、思い出として記録する対象。
- 思い出アルバムや可視化の主役である。

### Area

- 会場内の区分。
- Pavilion をグループ化して見せるために使う。

### Spot

- 地図上の位置情報。
- 将来の地図機能で使う可能性がある。
- 現時点では、ヒートマップや思い出アルバムの主軸にしない。

---

## 判断原則

- `docs/product/overview.md` の用語と体験価値を優先する。
- UI よりドメインを優先する。
- 既存の本番画面を壊さない。
- route / page / component の追加より、既存画面の最小修正を優先する。
- 大規模な DB スキーマ変更を避ける。DB 変更が必要な場合は `supabase/AGENTS.md` に従う。
- 確定したプロダクト方針だけを `docs/product/` に残す。
