# Bloomlog 制覇マップ Prototype 方針

## 0. 目的

この文書は、`/collection-next` の制覇マップ prototype をレビューし、次の prototype を **白地図ベースの制覇マップ** として磨くための product / UX / visual direction を整理する。

2026-05 時点では、prototype 実装として会場外形をベースにしたゾーン付きマップ画像を下敷きにし、その上に Pavilion の訪問済み / 未訪問状態を重ねる方向へ進めている。

直近の `/collection-next` prototype では、地図を一枚絵として眺める構成に加え、地図内ズーム / パン、訪問済み Pavilion の花びら + サムネイル表現、将来の固定座標化に向けた map config 分離を検証している。

参照:

- `docs/product/ux-review.md`
- `docs/product/output-ux-visual-direction.md`
- `app/collection-next/blooming-venue-map.tsx`
- `app/collection-next/page.tsx`

---

## 1. 再設計の結論

Bloomlog の map-based output UX は、「抽象アート」や「分析ダッシュボード」ではなく、**会場を埋めていく白地図ベースの制覇マップ** を主軸にする。

現時点の prototype 方針は、以下を優先する。

- 会場外形が分かる白地図 / ゾーン付きマップを主役にする。
- 右側の説明ペインや管理パネルを置かず、地図を一枚絵として眺められる構成にする。
- タイトル、訪問数、未訪問数、最小凡例は地図余白へ統合する。
- 「咲く」世界観は地図上の花 / つぼみ表現で伝え、説明文で押し出しすぎない。
- 制覇マップでは訪問済み / 未訪問だけに集中する。

制覇マップの役割はシンプルに、ユーザーがあとから見たときに、

- ここに行った
- ここはまだ行っていない
- 次はここに行きたい

を空間的に分かるようにすることである。

訪問回数、推し館、訪問傾向、写真、メモの濃さは、思い出アルバムや将来的な統計側の役割とする。制覇マップでは情報量を絞り、**visited / unvisited** を最優先する。

## 2. 現在の prototype レビュー

現在の `BloomingVenueMap` は、以下を実現している。

- ゾーン付き会場マップ画像を下敷きにし、地図そのものを主役にしている。
- Pavilion を訪問済みの花 / 未訪問のつぼみとして地図上に重ねている。
- 右ペインを廃止し、タイトル、訪問数、最小凡例を地図余白へ統合している。
- Treemap よりも、会場を眺める一枚絵としての成果物に寄せている。
- 地図はドラッグで移動でき、`+ / -` やトラックパッド操作で地図内ズームできる。
- 背景地図と Pavilion marker を別レイヤーに分け、拡大時に marker 自体が背景と同じ倍率で巨大化しない構造にしている。
- 訪問済み Pavilion は花びらの中央に Pavilion サムネイルを置く表現を検証している。
- Area / Pavilion の配置設定を `venue-map-config.ts` に分離し、将来の固定座標整備に備えている。

一方で、prototype としては課題が残る。

### 課題

1. **Pavilion の仮配置精度**
   - 現在は Area ごとの seed 配置であり、実際の Pavilion 位置とはまだ粗い。
   - 「この辺りを歩いた」感覚を強めるには、ゾーン内での配置調整が必要。
   - 最終的には全 Pavilion を固定座標で管理し、seed 配置は fallback として扱う。

2. **地図と花 / つぼみの馴染み**
   - 訪問済みの花は主役だが、地図を覆いすぎると会場感が弱くなる。
   - 未訪問のつぼみは分かる必要があるが、点一覧のように見せすぎない。
   - サムネイル付きの花は「記憶の手がかり」として有効だが、画像一覧化しないようサイズと密度を調整する。

3. **モバイルでの一枚絵感**
   - 地図を大きく使う方針はよいが、狭い画面ではタイトルや数字が地図を邪魔しやすい。
   - スクロール前提にするか、切り出し比率を変えるかは今後確認する。

4. **共有用画像への切り出し**
   - 一枚絵化したことで X 共有カードへ展開しやすくなった。
   - ただし、共有時に文字と地図が小さくなりすぎない構図調整が必要。

5. **エリア制覇時の Area 面表現**
   - Area 内の Pavilion をすべて訪問したとき、その Area 面全体が控えめに色づく表現を検証中。
   - 制覇感を出せる一方で、訪問済み / 未訪問の二値理解を邪魔しない濃度に留める。

## 3. 次の prototype 方針

次の prototype は、**会場外形を感じられる白地図ベースの一枚絵** として磨く。

### 3-1. 白地図ベース

白地図とは、公式地図画像や公式素材のコピーではなく、以下を持つマップである。

- 会場全体の輪郭やゾーン構造
- 北側会場 / 南側展示エリアなどの主要なまとまり
- Area の境界または面
- Pavilion の点、区画、または小さな花壇
- 入場ゲートや主要動線の最低限の目印
- 川や大きな分断要素など、空間記憶に効く要素

白地図は「公式案内図」ではない。ユーザーが自分の訪問体験を思い出すための成果物である。

### 3-2. 公式地図との距離

公式地図画像、公式素材、公式ロゴ、公式キービジュアルは使わない。

ただし、会場の基本構造を理解するため、公開情報や非公式マップから以下のような「関係性」は参考にできる。

- 北側に主会場的なまとまりがある
- 南側に展示エリアが続く
- 会場内に川や通路のような空間的な分断・導線がある
- Pavilion / 展示が複数のまとまりに分かれている

取り込むのは公式の画像や意匠そのものではなく、**Bloomlog 独自に再構成した空間関係** である。prototype では、ユーザー提供の参考画像を `public/prototypes/venue-map-zones.png` として使い、白地図ベースの見え方を検証する。

### 3-3. Area と Pavilion の見せ方

次の prototype では、Area と Pavilion の役割を分ける。

| 要素 | 表現 | 役割 |
| --- | --- | --- |
| 会場全体 | 薄い輪郭、白地図の地形 | 空間の舞台 |
| Area | 淡い面、区画、花壇 | どの一帯を回ったか |
| Pavilion | 点、小区画、つぼみ、花 | 訪問対象 |
| 訪問済み Pavilion | 色づいた花 / 点 / 小区画 | 行った場所 |
| 未訪問 Pavilion | 薄い輪郭 / つぼみ / 白い点 | まだ行っていない場所 |

Area だけを色づけると分かりやすいが、制覇感が粗くなる。Pavilion だけを出すと細かすぎる可能性がある。最初は **Area 面 + Pavilion 点** の二層構造がよい。

## 4. 状態表現

訪問状態は、数値ではなく **行った / 行っていない** の二値を地図上の変化で伝える。

### 未訪問

- 白地図の中に、淡い輪郭や小さなつぼみとして表示する。
- 「欠けている」「未達成で悪い」ではなく、「これから咲く場所」として見せる。
- 未訪問も地図上に存在させることで、「まだここが残っている」が分かる。

### 訪問済み

- Pavilion 点または小区画が花博らしく色づく。
- Area 面も、訪問済み Pavilion がある範囲として控えめに色づく。
- 複数回訪問、写真あり、メモありによる追加強調は、この prototype では扱わない。

---

## 5. Layout 方針

現在の第一候補は、**一枚絵 / ポスター型の制覇マップ** である。

### 5-1. 一枚絵 / ポスター型

構成:

- 右ペインを置かない。
- 地図をセクション全体の主役にする。
- `制覇マップ` / `訪問の記録` は左上の余白に小さく置く。
- `訪問済み / 全体` と `未訪問` は下側余白に置く。
- 凡例は必要最小限にする。
- 説明文は置かない。

良い点:

- 管理画面感が減る。
- 地図を眺める成果物として成立しやすい。
- X共有カードへ展開しやすい。
- 「読む」より「見返す」体験に寄る。

リスク:

- 補足説明がないため、初見で記号の意味が分かりにくい可能性がある。
- モバイルで余白に置いた数字や見出しが地図を邪魔する可能性がある。

扱い:

- 現在の `/collection-next` prototype の主軸。
- 次の調整もこの構成を維持したまま進める。

## 5-2. Area 面 + Pavilion 点

Area を淡い面として配置し、その中に Pavilion 点を置く。

良い点:

- 白地図として分かりやすい。
- Area と Pavilion の関係を表現しやすい。
- 未訪問 Pavilion をつぼみとして出せる。

リスク:

- Pavilion の座標データがない場合、仮配置が必要。
- 点が多いと混雑する。

扱い:

- 次 prototype の第一候補。
- まずは固定の seed 配置でよい。

## 5-3. Area 花壇 + Pavilion タイル

Area ごとに花壇のような区画を作り、その中に Pavilion を整列配置する。

良い点:

- 公式地図模倣を避けやすい。
- 未訪問 / 訪問済みが一覧として分かりやすい。
- モバイルでも破綻しにくい。

リスク:

- 実際の会場を歩いた感覚はやや弱い。
- 空間的なつながりが案 A より薄い。

扱い:

- 案 A が複雑すぎる場合の代替。

## 5-4. 抽象マップ + 白地図レイヤー追加

現在の抽象マップを土台に、未訪問 Pavilion と Area 境界を追加する。

良い点:

- 既存 prototype を活かせる。
- 実装差分が小さい。

リスク:

- もともとの抽象度が高いため、白地図感の限界がある。
- 花マーク中心の印象が残りやすい。

扱い:

- 現時点では保留。
- 本命 prototype は、会場外形ベースの一枚絵へ寄せる。

---

## 6. 現在の抽象マップの扱い

過去の抽象 `BloomingVenueMap` は、捨てる必要はない。ただし、本命の制覇マップとして進めるより、以下の位置づけがよい。

- **短期**: map-based output UX の初期検証として参照する。
- **現在**: 会場外形ベースの白地図 / ゾーン付きマップへ置き換える。
- **長期**: X共有カードや空状態のビジュアルとして一部の「咲く」表現を再利用する。

つまり、抽象マップは「咲く感覚の検証」として価値があった。一方で、制覇感・空間記憶・未訪問の期待感を担うには不足していたため、主軸からは外す。

## 7. 最小 prototype 案

次に実装するなら、最小 prototype は以下がよい。

### Prototype 1: White Map Poster: visited/unvisited only

目的:

- 白地図ベースの見え方を確認する。
- 公式地図コピーではなく、Bloomlog 独自の簡略マップとして成立するかを見る。
- Pavilion ごとの visited / unvisited が直感的に分かるかを見る。

内容:

- `/collection-next` の上段 map を一枚絵として置く。
- 会場外形とゾーンが分かる白地図 / 参考マップを下敷きにする。
- Pavilion の仮点を各 Area に配置する。
- 訪問済み Pavilion は既存 `pavilionItems` から花博らしく色づける。
- 未訪問 Pavilion は固定 seed の淡いつぼみとして表示する。
- 訪問回数、写真、メモ、サムネイルは表示しない。
- 右ペインは置かず、数字と最小凡例を地図余白に統合する。

制約:

- DB 変更なし。
- Pavilion の正確な座標がなくてもよい。
- 座標はまずコード内の seed として持つ。
- 公式マップの線や画像を写さない。
- prototype 用の参考画像は、本番素材ではなく検証用として扱う。

### Prototype 2: Area-first White Map

目的:

- Pavilion 座標なしでも、制覇感を出せるか見る。

内容:

- Area 面を主役にする。
- 訪問済み Pavilion 数に応じて Area 面が色づく。
- Area 内に小さなつぼみ / 花を数で表示する。

扱い:

- Prototype 1 が細かすぎる場合の fallback。

### 保留: multiple visits / 推し館表現

以下は制覇マップの第一 prototype では扱わない。

- 複数回訪問による濃淡や花びらの重なり。
- 写真あり / メモありの強調。
- 推し館や訪問傾向の表示。

これらは思い出アルバム、来場日サマリー、または将来的な統計側の役割として扱う。

Pavilion サムネイルは例外的に、訪問済みの花の中央に小さく入れる prototype を検証している。これは写真枚数やメモ量を示すためではなく、「その Pavilion に行った記憶」を地図上で識別しやすくするための補助表現である。制覇マップの主語は引き続き visited / unvisited であり、サムネイル一覧 UI には寄せない。

## 8. 実装時の注意

次に実装する場合、以下を守る。

- 入力UXに影響を与えない。
- `/collection-next` の検証ページ内で進め、本番 `/collection` への影響を分ける。
- 公式地図画像や公式素材を取り込まない。
- 非公式マップを参考にする場合は、出典リンクを明示し、画像や線のコピーではなく構造理解に留める。
- 数値ダッシュボード化しない。
- 「白地図 + 咲く」表現を主役にし、カード群やグラフ群を増やさない。
- 訪問回数、推し館、写真、メモの濃さを制覇マップに持ち込まない。
- 地図背景、Area、Pavilion marker、操作 UI は責務を分ける。Pavilion marker は背景地図と同じ倍率で拡大しないよう、地図レイヤーの外側で座標だけ追従させる。
- Pavilion 座標は `venue-map-config.ts` のような専用設定に寄せ、component 内に散らさない。

## 9. 役割分担

制覇マップ、思い出アルバム、Treemap は役割を分ける。

| 表現 | 主な役割 | 扱う情報 | 現時点の位置づけ |
| --- | --- | --- | --- |
| 制覇マップ | 行った / 行っていないを空間的に示す | Pavilion の visited / unvisited | 最優先 |
| 思い出アルバム | 訪問済みの記憶や個性を振り返る | 写真、メモ、訪問回数、代表サムネイル | 主力成果物 |
| Treemap | 訪問傾向や推し館を俯瞰する | 回数、偏り、Area / Pavilion の密度 | 現時点では保留 |

### 制覇マップが扱うこと

- 未訪問 Pavilion がどこに残っているか。
- 訪問済み Pavilion がどこにあるか。
- 会場全体のどのあたりが埋まっているか。
- 次に行きたい場所を見つけやすいこと。

### 制覇マップが扱わないこと

- 訪問回数。
- 推し館。
- 訪問傾向。
- 写真やメモの濃さ。
- ランキング、グラフ、詳細な集計。

これらは、思い出アルバムや将来的な統計 / 分析ビューで扱う。

なお、訪問済み Pavilion の中央サムネイルは「写真やメモの濃さ」ではなく、Pavilion 識別と記憶の手がかりとして限定的に扱う。サムネイルの有無・枚数・品質を達成度に見せない。

## 10.5. 直近 prototype の積み残し

次の実装ブラッシュアップでは、以下を優先する。

1. **背景地図の整備**
   - 現在の prototype 用画像をもとに、より Bloomlog 独自の白地図として整える。
   - 公式素材や公式意匠のコピーではなく、会場構造を理解できる独自の下敷きにする。

2. **全 Pavilion の固定座標プロット**
   - 各 Pavilion の座標を `venue-map-config.ts` に追加していく。
   - seed / fallback 配置は、座標未整備データの暫定表示として残す。
   - 座標調整しやすいよう、Area ごとのまとまり、命名、コメントを整理する。

3. **Area 制覇時の色づき**
   - Area 内の全 Pavilion が visited になった場合、Area 面を控えめに色づける。
   - 未訪問 Pavilion が残っている Area では、Area 全体を強く塗らない。
   - 色づきは制覇感の補助であり、Pavilion の visited / unvisited を隠さない。

4. **ズーム / パンの操作感**
   - 地図内 `+ / -`、ドラッグ、トラックパッド操作が同じズームモデルで動くことを維持する。
   - ブラウザ全体の拡大縮小と地図内ズームが混ざらないようにする。
   - 拡大時に Pavilion marker の見た目サイズは固定し、座標だけ背景地図に追従する。
   - mobile の pinch / pan は実機で確認する。
   - viewport の初期位置は、会場全体が自然に収まるように調整する。

5. **花 + サムネイル marker の微修正**
   - 花として一目で分かる外形を維持する。
   - 中央サムネイルは Pavilion 識別に十分なサイズを確保する。
   - marker が増えたとき、地図を覆いすぎない密度とサイズへ調整する。
   - hover / focus 時には Pavilion 名と訪問状態が分かるようにする。
   - animation は初回表示の気持ちよさを優先しつつ、marker 数が増えた場合の負荷を確認する。

6. **X共有カードへの展開**
   - 一枚絵として切り出したとき、地図、訪問数、花が読めるか確認する。
   - 共有画像では説明文を増やさず、「今日ここまで咲いた」が伝わる構図を優先する。

---

## 10. X共有カードでの扱い

X共有カードでも、制覇マップは visited / unvisited を主役にする。

共有時に伝わるべきこと:

- 「今日ここまで咲いた」
- 「まだここが残っている」
- 「会場のこの一帯を埋めた」

共有カードで避けること:

- サムネイルを大量に並べる。
- 凡例や数値を詰め込む。
- 訪問回数や推し館を強調する。
- 地図より画像カードや統計カードの集合に見えること。

---

## 11. 次の最小 prototype

次の最小 prototype は、**White Map Poster: visited/unvisited only** を第一候補にする。

内容:

- 会場外形とゾーン構造を白地図として見せる。
- 各 Area に Pavilion 点を seed 配置する。
- 未訪問 Pavilion は白いつぼみ / 薄い点として表示する。
- 訪問済み Pavilion は花博らしく色づける。
- hover / tap または SVG title で Pavilion 名だけを表示する。
- 訪問回数、写真、メモ、サムネイルは表示しない。

この prototype の目的:

- 未訪問 Pavilion が分かり、そこを制覇したくなるか確認する。
- 訪問済み Pavilion が花博らしく色づき、会場を埋めていく感覚があるか確認する。
- 情報量を絞っても、成果物として見返したくなるか確認する。
- Treemap や思い出アルバムと役割が混ざらないか確認する。
- 一枚絵 / ポスターとして見返したくなるか確認する。

## 12. まとめ

Bloomlog の制覇マップは、抽象アートではなく、会場を埋めていく白地図であるべき。花博らしく咲く表現は重要だが、それは地図の上に乗る状態表現であり、地図構造の代わりにはならない。

次の prototype は、**White Map Poster: visited/unvisited only** として進める。未訪問を淡いつぼみとして残し、訪問済みを花博らしく色づけることで、「今日ここまで咲いた」と「次はここに行きたい」を同時に成立させる。

訪問回数、推し館、写真、メモ、Pavilion サムネイルは、制覇マップの主軸にしない。それらは思い出アルバムや統計側で扱い、制覇マップは「行った / 行っていない」を直感的に示す成果物として磨く。
