# Bloomlog UX / 画面構成レビュー（2026-05-15）

## 0. 前提

- 対象資料: `AGENTS.md`, `app/AGENTS.md`, `docs/product/overview.md`, `docs/product/dev.md`, `docs/product/current-status.md`。
- 対象画面: Home / 来場日一覧 / 来場日詳細 / 思い出アルバム / 記録フォーム。
- 本レビューは **docs-only**（コード変更なし）であり、実装案は「最小変更」で段階導入できるものを中心にする。
- 目標体験: 「長文で思い出を書くアプリ」ではなく、**現地では爆速で記録でき、あとから見返したくなる成果物が育つアプリ**。
- 参照トーン: 自然・未来・公共イベント感（横浜花博公式サイトのような空気感）を参考にしつつ、公式デザイン／ロゴ／キービジュアル／地図意匠の流用や模倣は行わない。

---

## 1. 総評（現状）

Bloomlog は「来場日」単位で情報を積み上げる構造が明確で、ドメイン整合性も高い。現地利用に必要な入力効率も一定程度成立している。

一方で、現在の UI は記録された情報を「あとから見返したくなる成果物」へ変換する力がまだ弱い。特に「その日らしさ」「会場を回った実感」「X などで共有したくなる見た目」が薄く、結果として“よくできた記録台帳”に見えやすい。

Bloomlog の UX は、以下の二層構造として扱う。

- **入力UX**: 爆速・低負荷・現地向け。人混み、暑さ、移動中、通信不安定を前提に、最小タップと短い入力で思い出を残せることを最優先する。
- **出力UX**: 情緒・達成感・共有・振り返り向け。入力された断片を、思い出アルバムや制覇マップなどの「見返したくなる成果物」に変換する。

課題は、入力を重くして意味を増やすことではなく、**軽い入力から豊かな出力を生成する編集不足**（情報→記憶→共有したくなる成果物への変換不足）にある。

---

## 2. 体験方針（レビュー観点）

以下を UX の判断軸にする。

1. **入力UXは現地最優先**
   - 長文入力、複雑な選択、保存前の必須項目増加は避ける。
   - その場では「場所を選ぶ」「種類を選ぶ」「短く残す」だけで成立させる。
2. **出力UXは成果物として育てる**
   - あとから見返したときに、来場日や訪問エリアの記憶が一瞬で戻るか。
   - X などで共有したときに「今日ここまで咲いた」「このエリアをかなり回った」と伝わるか。
3. **1 来場日の物語化**
   - その日の空気・ハイライト・余韻が短時間で把握できるか。
   - ただし、物語化は現地入力の負担ではなく、保存済みデータの編集・表示で実現する。
4. **公共イベントらしい安心感**
   - 明るく整然、過剰演出せず、誰でも迷わないか。
5. **自然・未来のトーン**
   - 緑・空気感・余白・静かなアクセントで、見返し時の心理負荷を下げられるか。
6. **最小変更での実現性**
   - 既存 route / component 責務内で段階導入できるか。

---

## 3. 入力UXと出力UXの分離

### 3-1. 入力UX

入力UXの目的は、現地で「記録しきれなかった」を防ぐこと。思い出の文章化や美しい編集は、この段階で要求しない。

- 記録フォームは短時間・片手操作・低通信品質でも使えることを優先する。
- メモは任意の短文でよく、長文を書くことを成功条件にしない。
- 補助文言は「何を書けばいいか」を軽く助ける程度にし、入力欄やステップを増やしすぎない。
- 写真、メモ、詳細情報は後から追記できる前提にする。

### 3-2. 出力UX

出力UXの目的は、軽く残した思い出を「見返したい」「共有したい」成果物へ変換すること。

- **思い出アルバム**: 種類別・横断的に思い出を眺める成果物。
- **花博らしく色づく制覇マップ / 会場マップ**: 訪問した場所に応じて、抽象化された会場マップが少しずつ花開いていく成果物。本命候補として検証する。
- **来場日サマリー**: 1日の行動を短く振り返る成果物。

出力UXでは、データ可視化の正確さよりも「空間的な思い出の再体験」を優先する。正確な公式地図の模倣ではなく、花博らしい抽象化された会場マップでよい。

---

## 4. 制覇マップ / 会場マップの位置づけ

「制覇マップ」は単なる達成率ダッシュボードではない。Bloomlog における本命の出力UX候補は、訪問体験によって会場が少しずつ花開いていくような **map-based output UX** である。

目指す方向:

- 訪問した Pavilion / Area に応じて、抽象化された会場マップの該当箇所が色づく。
- 花博らしく、花・緑・光・余白を使って「咲いていく」感覚を出す。
- 「何%達成」よりも「どのエリアに思い出が咲いたか」を主語にする。
- X 共有時に、1枚の画像やカードとして「今日ここまで咲いた」「このエリアをかなり回った」が伝わる。
- 公式ロゴ、公式素材、公式キービジュアル、公式地図の形状を流用・模倣しない。

Treemap 実験は、パビリオンやエリアの訪問状況を一覧ではなく視覚的に見せたいという文脈では有意義だった。ただし Treemap は放置すると analytics / dashboard 的なデータ可視化に寄りやすい。今後の主軸は Treemap ではなく、花博らしく色づく会場マップとし、Treemap は lessons learned / 補助検証として扱う。

## 5. 画面別レビュー

## 5-1. Home

### 現状の良い点

- 来場日開始の CTA（来場日を開く）が明確で、初回操作に迷いがない。
- サマリー件数により「積み上げ実感」は得られる。
- 「最近の来場日」「思い出アルバム」へのハブとして機能している。

### 課題

- 件数サマリーが中心で、**成果物として見返したくなる入口**がまだ弱い。
- 初手の CTA は分かりやすいが、再訪時に「前回の成果物を見たい」「今日の続きをすぐ記録したい」の分岐が薄い。
- ヒーロー文脈が汎用的で、公共イベントの“季節感/来場の高揚”がまだ弱い。

### 改善提案（優先順）

1. **「最近の思い出」ショートセクションを追加**
   - 例: 最新 1〜3 件の写真サムネ + 一言メモ抜粋 + 来場日リンク。
   - 入力導線を邪魔せず、出力UXへの入口を作る。
2. **Home の主 CTA を現地向けに二層化**
   - 第1 CTA: 「最近の来場日を開く」
   - 第2 CTA: 「新しい来場日を開く」
   - 再訪ユーザーはすぐ続きを記録でき、初回ユーザーも迷わない構造にする。
3. **制覇マップの小さなプレビュー枠を検証**
   - 例: 「今日ここまで咲いた」を小さな抽象マップで表示。
   - Home 全体をダッシュボード化せず、成果物への誘導に留める。

---

## 5-2. 来場日一覧

### 現状の良い点

- 来場日単位のリスト構造が分かりやすい。
- 日付・タイトル・メモで最小限の判別が可能。

### 課題

- リスト項目がテキスト中心で、**どの日を開くと何が思い出せるか**の判断材料が薄い。
- 各来場日の密度（思い出件数、カテゴリ偏り、写真有無）が見えず、選択コストが高い。

### 改善提案（優先順）

1. **来場日カードに「サマリーチップ」を追加**
   - 例: 思い出件数 / 写真あり件数 / パビリオン数。
   - これは入力を増やすためではなく、既存データから日の特徴を見せるために使う。
2. **最新更新の明示**
   - 例: 「最終記録: 5月10日 18:20」など。
   - 現地で直近の続きを開きやすくする。
3. **視覚フックの追加**
   - 各行の左端に小さな代表サムネ（あれば）を表示。
   - 一覧から“日の記憶”を引き出す。

---

## 5-3. 来場日詳細

### 現状の良い点

- 1 画面内に「記録フォーム」「サマリー」「タイムライン」が揃っており完結性が高い。
- サマリー件数で活動量が把握しやすい。
- タイムラインの時系列表示は「行動の再構成」に有効。

### 課題

- 現地利用では記録フォームがすぐ使えることが重要だが、見返し時には成果物としての印象が弱い。
- その日の意味を圧縮した「今日の印象」レイヤーがなく、件数情報止まり。
- タイムラインがイベント列挙になりやすく、余韻設計が弱い。

### 改善提案（優先順）

1. **記録導線は上部に残しつつ、見返し用の「この日の印象」ブロックを追加**
   - 例: タイトル・ひとこと・カテゴリハイライト（仕様にある Summary 強化方針と整合）。
   - 入力より振り返りを常に上に置く、という意味ではない。現地ではすぐ記録、あとからは気持ちよく振り返れる二層構造にする。
2. **入力モードと見返しモードの視覚的な役割分担**
   - 記録フォームは軽く、短く、迷わない。
   - サマリー / タイムライン / 制覇マップ導線は成果物として見せる。
3. **タイムラインの節目表現**
   - 例: 朝/昼/夕の区切りラベル、最初と最後の思い出強調。
   - 追加入力なしで「1日の物語感」を出す。

---

## 5-4. 思い出アルバム

### 現状の良い点

- カテゴリ横断の振り返り導線として有効。
- パビリオンを集約表示する方針は、再訪傾向の把握に適している。
- 検索・カテゴリ絞り込みがあり、探索性は高い。

### 課題

- 検索/絞り込み UI が主語になり、**「眺める楽しさ」より「探す作業感」が強い**。
- セクション間の意味差（なぜパビリオンは集約で他は個別か）が伝わりにくい。
- 「記憶に残った順」「印象の強さ」ではなく、ほぼ時系列/件数軸に留まる。
- 出力UXの本命候補である制覇マップ / 会場マップとの関係がまだ定義されていない。

### 改善提案（優先順）

1. **アルバム冒頭に「今月の思い出」帯を追加**
   - 自動抽出例: 写真あり・メモあり・直近の組み合わせから 3 枚。
2. **制覇マップ / 会場マップへの導線を追加**
   - 「思い出アルバム」は横断して眺める成果物。
   - 「制覇マップ」は空間的に再体験する成果物。
   - どちらも出力UXだが、Bloomlog らしさの本命検証は map-based output UX に置く。
3. **セクションの意味を一文で明示**
   - パビリオン: 「訪問履歴を重ねて振り返る」
   - フード等: 「その時の体験を個別に振り返る」
4. **カードの余韻強化**
   - メモ抜粋をモバイルでも短く表示（1行）し、記憶トリガーを増やす。

---

## 5-5. 記録フォーム

### 現状の良い点

- 種類選択後に必要項目のみ表示され、入力認知負荷は低い。
- エラーハンドリング・状態管理が丁寧で、実務運用に強い。
- パビリオン検索と選択の導線が明確。

### 課題

- UX の重心が「正しく入力する」に寄っており、**軽く残した断片がどう成果物に育つか**が見えにくい。
- メモ入力が自由記述のみで、何を書けば後で思い出しやすいかのガイドが薄い。
- 保存後の達成演出が弱く、「思い出が増えた」「マップが咲いた」実感が出にくい。

### 改善提案（優先順）

1. **メモ欄に軽いプロンプトを追加**
   - 例: 「印象に残った色・音・会話を1つだけ」など。
   - 文章力ではなく想起しやすさを支援する。長文入力を促す意図ではない。
2. **保存後フィードバックを“成果物が育つ”トーンへ**
   - 例: 「思い出を追加しました」に加えて、該当エリアが色づく・咲く表現を将来的に検証する。
3. **最小入力→追記の二段階化（将来）**
   - まず種類 / 対象 / 時刻程度で保存し、後からメモや写真を追記しやすくする。
   - 現地入力を重くしないことを最優先にする。

## 6. 雰囲気設計ガイド（自然・未来・公共イベント感）

※ 公式意匠の模倣ではなく、体験トーンのみ参照。

- **色**: 低彩度の緑・空色・生成りを基調に、情報色は既存トーンを維持。
- **マップ表現**: 公式地図の正確な再現ではなく、抽象化された会場の面・道・エリアを、訪問に応じて花博らしく色づける。
- **余白**: カード内の呼吸を広め、詰め込み感を抑える。ただし現地入力フォームは縦に長くしすぎない。
- **タイポ**: 日本語可読性優先、見出しは短く、本文は落ち着いた行間。
- **モーション**: 過剰アニメーションは避け、保存後やマップ更新時に控えめな変化で達成感を出す。
- **言葉**: 命令調よりも「思い出す」「振り返る」「咲いた」を促す文体。入力時は短く、出力時は情緒を持たせる。

## 7. Treemap 実験の学び

Treemap は、パビリオンやエリアの訪問状況を一覧ではなく視覚的に見せる実験として有意義だった。特に「訪問済みの偏り」「エリアごとの密度」「まだ行っていない場所」を俯瞰する用途には向いている。

ただし、Bloomlog が目指す中心価値は analytics / dashboard 的な可視化ではない。Treemap は数値や面積の読み取りに寄りやすく、放置すると「オタクっぽいデータ可視化」になりやすい。

今後の扱い:

- 主軸: 花博らしく色づく制覇マップ / 会場マップ。
- 補助: Treemap で得た「一覧ではなく視覚的に達成感を出す」学び。
- 避けること: Treemap をそのまま本命 UI として採用し、達成率ダッシュボード化すること。

## 8. X共有を前提にした成果物観点

Bloomlog の出力UXは、アプリ内で見返すだけでなく、X などで共有したくなることを目指す。

共有されるべきもの:

- 今日の来場日サマリー。
- 今月の思い出アルバムの一部。
- 花博らしく色づいた制覇マップ / 会場マップ。

共有時に伝わるべきこと:

- 「今日ここまで咲いた」
- 「このエリアをかなり回った」
- 「この日の思い出が増えた」

共有カードは、公式素材を使わず、Bloomlog 独自の抽象表現で成立させる。データ可視化として正確すぎる必要はなく、見た人が「楽しそう」「自分も記録したい」と感じる成果物であることを優先する。

## 9. 実装優先度（最小変更前提のロードマップ）

### Phase 1（低コスト・高効果）

- Home に「最近の思い出」追加。
- 来場日一覧に来場日サマリーチップ追加。
- 記録フォームのメモ補助文言追加。
- 保存後フィードバックの文言を「思い出が増えた」トーンへ調整。

### Phase 2（中コスト）

- 来場日詳細に「この日の印象」ブロック追加。
- タイムライン節目表現の追加。
- 思い出アルバム冒頭の「今月の思い出」帯追加。
- 思い出アルバムから制覇マップ / 会場マップへの導線を追加。

### Phase 3（検証）

- map-based output UX の検証。
  - 抽象化された会場マップの表現方針。
  - Pavilion / Area の訪問状態に応じた色づき方。
  - X 共有カードとしての見え方。
  - 公式地図・公式意匠を模倣しないための表現境界。
- 振り返りファーストの画面順再構成（詳細画面の情報順最適化）。
- 印象ベースの並び替え（将来的なスコアリング）検討。

## 10. KPI / 検証観点

入力UXと出力UXを分けて検証する。

### 入力UX

- 現地での記録完了時間。
- 記録フォームの離脱率。
- 最小入力で保存された思い出数。
- メモ入力率・写真添付率の推移。

### 出力UX

- 思い出アルバムの再訪率。
- 制覇マップ / 会場マップの閲覧率。
- 記録後 7 日以内の再閲覧率。
- X 共有導線のクリック率 / 共有意向。

定性では、

- 「現地で負担なく記録できるか」
- 「開いた瞬間にその日を思い出せるか」
- 「マップが咲いていく感覚があるか」
- 「X に共有したくなる成果物になっているか」

をユーザーテストで確認する。

## 11. まとめ

Bloomlog は土台が強く、現時点で「来場日」単位の記録アプリとしては成立している。次段階は、入力を重くすることではなく、**爆速で残した思い出を、あとから見返したくなる成果物へ変換すること**。

思い出アルバムは重要な出力UXであり続ける。一方で、Bloomlog らしさの本命候補は、訪問体験によって会場が少しずつ花開いていく **花博らしく色づく制覇マップ / 会場マップ** にある。Treemap の学びは活かしつつ、主軸は map-based output UX として検証する。
