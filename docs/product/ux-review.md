# Bloomlog UX / 画面構成レビュー（2026-05-15）

## 0. 前提

- 対象資料: `AGENTS.md`, `app/AGENTS.md`, `docs/product/overview.md`, `docs/product/dev.md`, `docs/product/current-status.md`。
- 対象画面: Home / 来場日一覧 / 来場日詳細 / 思い出アルバム / 記録フォーム。
- 本レビューは **docs-only**（コード変更なし）であり、実装案は「最小変更」で段階導入できるものを中心にする。
- 目標体験: 「記録アプリ」ではなく、**あとで思い出を気持ちよく振り返れるアプリ**。
- 参照トーン: 自然・未来・公共イベント感（横浜花博公式サイトのような空気感）を参考にしつつ、公式デザイン／ロゴの模倣は行わない。

---

## 1. 総評（現状）

Bloomlog は「来場日」単位で情報を積み上げる構造が明確で、ドメイン整合性も高い。一方で、現在の UI は **入力効率と一覧性に寄っており、感情想起（= 思い出の再体験）への橋渡しが弱い**。  
特に「その日らしさ」「印象の余韻」「見返したくなる手触り」がまだ薄く、結果として“よくできた記録台帳”に見えやすい。

言い換えると、課題は機能不足よりも **意味の編集不足**（情報→記憶への変換不足）にある。

---

## 2. 体験方針（レビュー観点）

以下を UX の判断軸にする。

1. **再体験の導線**
   - 「入力する」より先に「思い出す」モードへ入れるか。
2. **1 来場日の物語化**
   - その日の空気・ハイライト・余韻が短時間で把握できるか。
3. **公共イベントらしい安心感**
   - 明るく整然、過剰演出せず、誰でも迷わないか。
4. **自然・未来のトーン**
   - 緑・空気感・余白・静かなアクセントで、見返し時の心理負荷を下げられるか。
5. **最小変更での実現性**
   - 既存 route / component 責務内で段階導入できるか。

---

## 3. 画面別レビュー

## 3-1. Home

### 現状の良い点

- 来場日開始の CTA（来場日を開く）が明確で、初回操作に迷いがない。
- サマリー件数により「積み上げ実感」は得られる。
- 「最近の来場日」「思い出アルバム」へのハブとして機能している。

### 課題

- 初手が「作成操作」に寄りすぎており、**振り返り導線より入力導線が強い**。
- 件数サマリーが中心で、**感情的な再想起トリガー（最近の1枚、最近のひとこと等）が不足**。
- ヒーロー文脈が汎用的で、公共イベントの“季節感/来場の高揚”がまだ弱い。

### 改善提案（優先順）

1. **「最近の思い出」ショートセクションを最上段に追加**
   - 例: 最新 1〜3 件の写真サムネ + 一言メモ抜粋 + 来場日リンク。
   - まず思い出してから記録に入る流れを作る。
2. **Home の主 CTA を二層化**
   - 第1 CTA: 「最近の来場日を開く」
   - 第2 CTA: 「新しい来場日を開く」
   - 既存の作成優先を維持しつつ、再訪ユーザーの振り返り行動を優先。
3. **トーン調整（視覚）**
   - 背景グラデーションは保持しつつ、カード内余白と行間を少し広げる。
   - 「自然・未来・公共」の静かな清潔感を強化（過度な装飾は不要）。

---

## 3-2. 来場日一覧

### 現状の良い点

- 来場日単位のリスト構造が分かりやすい。
- 日付・タイトル・メモで最小限の判別が可能。

### 課題

- リスト項目がテキスト中心で、**どの日を開くと“気持ちよく思い出せるか”の判断材料が薄い**。
- 各来場日の密度（思い出件数、カテゴリ偏り、写真有無）が見えず、選択コストが高い。

### 改善提案（優先順）

1. **来場日カードに「サマリーチップ」を追加**
   - 例: 思い出件数 / 写真あり件数 / パビリオン数。
2. **最新更新の明示**
   - 例: 「最終記録: 5月10日 18:20」など。
   - 直近の続きを開きやすくする。
3. **視覚フックの追加**
   - 各行の左端に小さな代表サムネ（あれば）を表示。
   - 一覧から“日の記憶”を引き出す。

---

## 3-3. 来場日詳細

### 現状の良い点

- 1 画面内に「記録フォーム」「サマリー」「タイムライン」が揃っており完結性が高い。
- サマリー件数で活動量が把握しやすい。
- タイムラインの時系列表示は「行動の再構成」に有効。

### 課題

- 現在は「記録エリア」が主役で、**振り返りエリア（サマリー/タイムライン）が従属**して見える。
- その日の意味を圧縮した「今日の印象」レイヤーがなく、件数情報止まり。
- タイムラインがイベント列挙になりやすく、余韻設計が弱い。

### 改善提案（優先順）

1. **来場日ヘッダー直下に「この日の印象」ブロックを配置**
   - 例: タイトル・ひとこと・カテゴリハイライト（仕様にある Summary 強化方針と整合）。
2. **情報階層の再配分**
   - 表示順の基本案: ヘッダー → この日の印象 → タイムライン → 記録フォーム。
   - 入力より振り返りを上位に置く。
3. **タイムラインの節目表現**
   - 例: 朝/昼/夕の区切りラベル、最初と最後の思い出強調。
   - 「1日の物語感」を出す。

---

## 3-4. 思い出アルバム

### 現状の良い点

- カテゴリ横断の振り返り導線として有効。
- パビリオンを集約表示する方針は、再訪傾向の把握に適している。
- 検索・カテゴリ絞り込みがあり、探索性は高い。

### 課題

- 検索/絞り込み UI が主語になり、**「眺める楽しさ」より「探す作業感」が強い**。
- セクション間の意味差（なぜパビリオンは集約で他は個別か）が伝わりにくい。
- 「記憶に残った順」「印象の強さ」ではなく、ほぼ時系列/件数軸に留まる。

### 改善提案（優先順）

1. **アルバム冒頭に「今月の思い出」帯を追加**
   - 自動抽出例: 写真あり・メモあり・直近の組み合わせから 3 枚。
2. **セクションの意味を一文で明示**
   - パビリオン: 「訪問履歴を重ねて振り返る」
   - フード等: 「その時の体験を個別に振り返る」
3. **カードの余韻強化**
   - メモ抜粋をモバイルでも短く表示（1行）し、記憶トリガーを増やす。

---

## 3-5. 記録フォーム

### 現状の良い点

- 種類選択後に必要項目のみ表示され、入力認知負荷は低い。
- エラーハンドリング・状態管理が丁寧で、実務運用に強い。
- パビリオン検索と選択の導線が明確。

### 課題

- UX の重心が「正しく入力する」に寄っており、**思い出を言語化しやすくする補助が不足**。
- メモ入力が自由記述のみで、何を書けば後で思い出しやすいかのガイドが薄い。
- 保存後の達成演出が弱く、「思い出が増えた実感」が出にくい。

### 改善提案（優先順）

1. **メモ欄に軽いプロンプトを追加**
   - 例: 「印象に残った色・音・会話を1つだけ」など。
   - 文章力でなく想起しやすさを支援。
2. **保存後フィードバックを“記録完了”から“思い出追加”トーンへ**
   - 文言・色・補助コピーを調整。
3. **最小入力→追記の二段階化（将来）**
   - まずタイトル/時刻のみ保存し、後からメモや写真を追記しやすくする。

## 4. 雰囲気設計ガイド（自然・未来・公共イベント感）

※ 公式意匠の模倣ではなく、体験トーンのみ参照。

- **色**: 低彩度の緑・空色・生成りを基調に、情報色は既存トーンを維持。
- **余白**: カード内の呼吸を広め、詰め込み感を抑える。
- **タイポ**: 日本語可読性優先、見出しは短く、本文は落ち着いた行間。
- **モーション**: 過剰アニメーションは避け、フェード/ホバー程度の静的な品位。
- **言葉**: 命令調よりも「思い出す」「振り返る」を促す文体。

## 5. 実装優先度（最小変更前提のロードマップ）

### Phase 1（低コスト・高効果）

- Home に「最近の思い出」追加。
- 来場日一覧に来場日サマリーチップ追加。
- 記録フォームのメモ補助文言追加。

### Phase 2（中コスト）

- 来場日詳細に「この日の印象」ブロック追加。
- タイムライン節目表現の追加。
- 思い出アルバム冒頭の「今月の思い出」帯追加。

### Phase 3（検証）

- 振り返りファーストの画面順再構成（詳細画面の情報順最適化）。
- 印象ベースの並び替え（将来的なスコアリング）検討。

---

## 6. KPI / 検証観点

「気持ちよく振り返れる」を検証するため、以下を計測候補にする。

- 来場日詳細での **閲覧滞在時間**（フォーム到達前）。
- 思い出アルバムの **再訪率**。
- 記録後 7 日以内の **再閲覧率**。
- メモ入力率・写真添付率の推移。

定性では、

- 「どの日を開くか迷わないか」
- 「開いた瞬間にその日を思い出せるか」
- 「見返して気分がよくなるか」

をユーザーテストで確認する。

---

## 7. まとめ

Bloomlog は土台が強く、現時点で「記録アプリ」としては成立している。次段階は、既存構造を崩さずに **思い出の意味編集レイヤー**を追加すること。  
特に Home / 来場日詳細 / 思い出アルバムで「件数情報」から「その日らしさ」へ重心を移すと、目的である「あとで思い出を気持ちよく振り返れるアプリ」に近づく。
